# Schedule Risk Predictor

Machine learning models that predict, from signals available when a
capital project is roughly 30 percent complete, whether the project will
finish more than 14 days late, and by how many days.

Built as a portfolio project in the shape of a real production problem:
schedule risk prediction for large construction and infrastructure
programs, where a late warning is only useful if it arrives early enough
to act on.

## Honest scope

The dataset is synthetic. It is generated by a documented process
(generate_data.py) built on earned value management relationships:
projects already behind schedule (low SPI) or over budget (low CPI) at an
early snapshot, carrying many change orders, procurement delays, rework,
dense dependencies, and little float, tend to finish late. Every label in
the data comes from that process plus noise, so the metrics below measure
how well the models recover a known signal. They are a methods
demonstration, not a claim about accuracy on real project portfolios.
With real data I would expect lower and messier numbers, and the same
pipeline is written to be re-run on real exports unchanged.

## Method

Features (all measured at the snapshot, nothing from the future, so no
target leakage): planned duration, budget, activity count, dependency
density, critical path ratio, subcontractor count, percent complete, SPI,
CPI, change orders so far, weather delay days so far, rework percent,
crew turnover, procurement delay days so far, average float days.

Targets: will_slip (delay over 14 days) and delay_days.

Three model families are compared on a held out 20 percent test set with
a fixed split: logistic regression, random forest, and histogram gradient
boosting. The winner of each task is saved and served.

## Results (held out test set, 480 projects)

Classification, winner logistic regression:
ROC AUC 0.941, accuracy 0.863, precision 0.845, recall 0.801, F1 0.823.
Random forest AUC 0.912, gradient boosting AUC 0.918. The additive
generative process favors a linear model; on real data the ranking would
likely flip to the tree models, which is itself a finding the comparison
is designed to surface.

Regression, winner histogram gradient boosting:
MAE 15.9 days, RMSE 21.5 days, R2 0.715.
Linear regression MAE 18.7 days, random forest MAE 18.8 days.

Strongest slip drivers by permutation importance: SPI, rework percent,
dependency density, change orders so far, procurement delay days so far,
average float days. These match how project controls teams actually read
risk, which is a basic sanity check on the pipeline.

## Run it

    python3 -m venv .venv
    .venv/bin/pip install scikit-learn pandas numpy joblib fastapi uvicorn
    .venv/bin/python generate_data.py
    .venv/bin/python train.py
    .venv/bin/python smoke_test.py
    .venv/bin/uvicorn app:app --reload

Then POST a snapshot to /predict (see app.py for the schema) and receive
a slip probability, a predicted delay in days, a risk band, and the top
drivers.

## What production would add

Ingestion from real schedule exports (Primavera P6, Microsoft Project)
and progress systems; training on historical portfolios with point in
time snapshots so evaluation stays leakage free; per portfolio
calibration; drift monitoring on SPI and CPI distributions; reviewer
feedback loops where planners confirm or override predictions and those
labels retrain the model; prediction clipping and uncertainty ranges
instead of point estimates.

## Layout

    generate_data.py   documented synthetic dataset generator
    train.py           model comparison, evaluation, artifact export
    predict.py         shared scoring logic
    app.py             FastAPI service
    smoke_test.py      healthy vs troubled project sanity check
    model/             trained artifacts and metrics.json
    data/              generated dataset
